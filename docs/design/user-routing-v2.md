# 用户路由、链式出站与 DNS：routing v2

要让某个账号的 GitHub 流量经中转 A 到住宅出口 B：先建立 A、B 两个出站连接，在 B 中选择“前置出站 A”；再添加域名规则，选择账号、填写 `geosite:github`，将出站设为 B。实际路径是 `ppnode → A → B → 目标`，不是连续命中两条路由。

## 保存前先升级相关节点

routing v2 不会重新转换已经完成切换的 `02180` 路由。本分支合入了官方的七个后续数据库迁移（`03000`、`03001`、`03020` 至 `03024`），涉及订阅权益、认证绑定、流量重置和支付订单。**升级前停止其他写入进程，备份现有数据库、配置和配套二进制。** 启动新版 backend 后，已完成切换的 `02180` 库应达到 `03024`，原有规则、revision、订阅 token/UUID 和用量应保留。仍在 `02179` 的 fork 安装须先通过[有序路由预检](ordered-node-routing.md)并完成 `02180` 切换。

先升级 backend 和管理端，再升级所有受影响的节点：新节点通过 `GET /v1/server/alivelist` 和 `POST /v1/server/device` 向 backend 申请并续用同一订阅的全局设备名额。限额按订阅和来源 IP 计数；同一 IP 跨节点、TCP/UDP 只占一个名额。新 IP 的准入失败不能放行有限额的订阅。最后再启用所需 v2 配置；旧节点请求 v2 会得到 HTTP 426，这不会关闭它已经运行的旧配置。

旧 `routing.version:1` 的格式、AsIs 路由与 UDP DNS 行为保留。管理端读取 v1 不自动改写；编辑账号范围、账号默认出站、前置出站或独立 DNS 策略时，才将该完整包升级到 v2。仅回退节点时，应先明确转换为 v1 策略并确认节点应用；涉及 v2 能力损失时必须显式确认。若要回退至升级前的 `02180` 后端，须停机恢复升级前数据库备份及匹配版本；把路由改回 v1 不会撤销数据库迁移。

## 用户范围与默认出口

- 管理端选择的是账号 `user.id`；后端按该服务器、协议和套餐授权，展开到有效 `user_subscribe.id`。多个订阅可属于同一账号，新取得授权的订阅继承该账号选择。
- `rules[].user_ids` 省略或为空表示全部用户；数组内部为 OR，与该规则的域名/IP/协议条件为 AND。目标列表内部仍为 OR，规则继续按列表顺序执行。
- 账号存在但没有有效订阅时，该账号范围匹配零身份，不得退化为全局规则。删除账号后的旧引用保留为零身份；新增引用必须指向存在的账号。
- `user_defaults: [{user_id,outbound_id}]` 每账号至多一项，处理路由完全未匹配的流量。它不是末尾的 user-only 全匹配规则，也不覆盖已经命中的 Google-CN、Apple 等明确出口。
- 节点仍使用 `入站tag|UUID` 作为认证和统计标签，不能改为登录邮箱或账号 ID。

v2 的路由使用 `IPIfNonMatch`。存在启用的 IP 条件时，待放行的域名目标会在拨号前带解析结果重新匹配，并固定经检查的目标 IP；选择“全部用户”不关闭这项检查。显式域名例外仍按其与 IP 规则的相对顺序生效，混合地址结果中被当前有序策略拒绝的地址不能通过随机选址绕过。解析失败时不以原域名继续交给上游解析来规避限制。没有配置 IP 条件时，不额外增加硬性私网/CN 规则；v1 不改变。

仅含启用 IP 规则的 v2 包也具有解析策略能力，降回 v1 的 AsIs 需要确认。客户端本地 DIRECT 不经过节点，节点规则无法管到这部分流量。

## 前置出站与引用

`outbounds[].via_outbound_id` 引用同包自定义出站的稳定 ID。不选前置时保持原连接方式；名称和排序变化不会改变引用。

前后端与节点验证自引用、循环、悬空引用。规则、账号默认、DNS 或另一出站仍引用某连接时，不能直接删除它；提交一个同时删除全部依赖的完整新包则是明确的配置变更。

既有 raw `stream_settings.sockopt.dialerProxy` 中的 `routing_<ob_id>` 参与同一引用图，`Default` 和 `block` 为内建终端；不能与非空结构化前置字段同时使用。其它合法 raw 设置保留，不因存在 raw 就一律拒绝。

TCP/UDP 能力取决于每一跳。已验证 SOCKS→SOCKS 的两种流量；HTTP CONNECT 不能转发 UDP，HTTP 前置下的 SOCKS UDP 路径会失败，不会自动改走直连。出站失败不跳过 A 或 B，不自动切换备用出口。

## 独立 DNS 策略

可选的 `routing.dns_policy` 与路由、出站一起保存和应用：

- `query_strategy`：`UseIP`、`UseIPv4`、`UseIPv6`。
- `resolvers[]`：稳定 `dns_<UUIDv4>` ID、`protocol`（`udp`/`tcp`/`https`）、`address`、`domains`、`outbound_id`，以及可选 `bootstrap_ip`。
- 按顺序首个域名/GeoSite 匹配生效，最后一项必须是 `domains:[]` 默认解析器。命中解析器失败，不回退到下一项、系统 DNS 或其它出口。
- `bootstrap_ip` 用于域名解析器的连接引导，UDP/TCP/DoH 均可使用；查询 A/AAAA 与引导连接所用 IPv4/IPv6 是不同维度。IP 字面解析器不需要引导 IP，同一主机不能配置冲突的引导值。
- 域名解析器或代理服务器可能产生“解析自身需要先连接自身”的依赖环。节点用实际 GeoSite 数据校验；通过引导 IP 或独立解析器打断环，不隐式使用系统 DNS。
- 内部 DNS 查询有独立标签与出站规则，位于普通 UDP/53 拦截之前，避免递归进入 DNS 出站。它不自动跟随用户默认出口。

启用显式 DNS 时不加入系统 localhost 解析器，不启用 `+local` 绕路模式；DoH 保留原主机名用于 TLS 校验。未配置 `dns_policy` 时，旧 DNS 字段及其独立继承行为不变。显式模式下管理端隐藏旧 DNS 编辑区，但保留其值以便切回。

这是节点 DNS，不自动改写 Clash 客户端 DNS，也不是逐用户 DNS。上游代理自行解析的部分不能被本地配置冒充为已控制；需要 IP 条件检查的路径会本地解析并固定目标。

## 一致性、回执与失败

v2 节点配置响应携带 `identity_snapshot`，包含每个启用协议的授权用户与不透明 `snapshot_id`。同一数据库 repeatable-read 快照读取配置、规则、账号和订阅；UUID 轮换、禁用、删除、额度/期限变化、续期和限制变化会反映到交付身份。节点不再另用独立用户轮询修改 v2 身份。

真实节点拉取保留原有 pending 订阅激活行为；管理员读取 desired 状态是只读的，遇到尚需激活的 pending 记录可返回未知，不会因查看页面启动订阅期限。

节点先纯编译候选并准备监听配置，再停止旧监听、结束旧流并切换核心，避免 Xray 进程全局 dialer 串用新旧出站。所有监听、用户及限制成功后才提交 applied；失败使用保存的旧配置恢复，恢复本身失败则关闭服务并报告错误。变更应用会断开原连接，未变化的轮询不会触发切换。流量上报队列跨切换保留。

管理端只有在 routing 身份和 `snapshot_id` 都对应当前 desired 时显示已应用。只看 revision 不足以证明用户身份同步；Redis 状态或交付过滤条件不可用时显示未知。保存、下载和 pending 都不表示已经应用。

v1 用户列表也修复了下载 ETag 提前提交与遗漏 Id/DeviceLimit 差异的问题：成功应用后才确认，失败重试，不把 304 当作此前失败候选已经生效。

## 接口与界面设置

全局仍用 `GET/PUT /v1/admin/system/node_config`，服务器仍用 `GET /v1/admin/server/node_config` 与 `POST /v1/admin/server/node_config/update`。非路由字段继续 partial 更新；更改路由带 `routing_revision` 和完整包，冲突为 HTTP 409。实际能力降级需要 `routing_downgrade:true`；local v2 切到 global v2 继承不是降级。

这些配置接口只允许经过授权的管理员访问：有序 routing 完整包包括出站凭据，管理员读取、复制和继承时返回实际值，不用 `********` 替代；该字符串也可以是实际密码。不得向非管理员开放这些完整包，也不得把包或凭据扩散到日志或前端持久缓存。Turnstile 密钥和汇率 access key 仍遵循各自设置接口的掩码契约。

节点优先声明 `X-PPanel-Routing-Version:2`；旧面板仅支持字面 v1 时有界重试一次头 1。新面板不会为头 1 剥掉 v2 条件，426 检查先于 ETag/304。JSON/protobuf 提供相同有效内容，原 wire 字段编号不变。

菜单显示是独立配置：系统设置→界面设置，使用管理鉴权 `GET/PUT /v1/admin/system/interface_config` 保存 `hiddenMenuIds`。所有管理员共用后台值；系统设置始终可达，可恢复全部显示。它只隐藏导航，不改变权限、功能或用户端。

本次不新增访问审计、自动探活、自动主备、负载均衡或上游出口订阅。
